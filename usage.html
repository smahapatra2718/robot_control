abb_foga usage guide

Browser-based teleop and a remote HTTP/WebSocket API for two arms — a Universal Robots UR15 and an ABB GoFa CRB 15000 — on a shared viser + pyroki stack.

tip  Every command block has a copy button on hover. The sidebar tracks your position.

Overview

One motion implementation drives everything. The same kinematics, IK, speed profile and safety logic back the viser teleop UIs, the headless recorders/players, and the remote API — so behavior never drifts between surfaces.

SurfaceWhat it isRun with
Teleop UIViser browser app: drag a gizmo, plan, play, live-follow, free-drive teachreal.py ur15 / gofa

Two ports to remember. The teleop UI serves viser on http://localhost:8080. The remote API serves on http://localhost:8000.

Quick start

Everything runs through two symmetric dispatchers — real.py (hardware) and sim.py (offline, no robot or network). They take the same arguments, so you can develop against the sim and switch one word to go live.

Build a command

./robot_control/bin/python scripts/sim.py ur15

First run (offline, no robot needed)

# offline sim — runs the real teleop against a perfect-tracking kinematic sim
./robot_control/bin/python scripts/sim.py ur15
# → open the printed URL:  http://localhost:8080

The sim still needs the project venv (it runs the real jax / pyroki / viser stack and real URDFs) — "offline" means no robot, not no Python deps.

Going live

./robot_control/bin/python scripts/real.py ur15     # UR15 over RTDE
./robot_control/bin/python scripts/real.py gofa     # GoFa over EGM
Each script connects at startup and aborts if it can't reach the arm. For the UR15, enable the RTDE/Dashboard/Primary services and Remote Control mode on the pendant. For the GoFa, push the EGM supervisor once with install_gofa_egm.py. See CLAUDE.md for the full controller bring-up.

Teleop UI workflow

The browser app follows a simple state machine. The arm mirrors into the browser while you author, then plays back what you planned.

Idle → Waypoints → Plan → Play
  1. Idle. The browser mirrors the live arm. Drag the 3-D gizmo to aim the tool.
  2. Add / Capture waypoint. Add snapshots the gizmo pose; Capture snapshots the live joints (and, on the UR, the current gripper opening). Each adds a numbered frame to the scene.
  3. Plan. Runs seeded IK through the waypoints — each solution seeds the next, so the path stays in one kinematic branch. With no waypoints it falls back to the gizmo pose.
  4. Play. Streams the planned motion. With Execute ticked it drives the real arm; otherwise it's a preview in the browser only.
The speed slider is unified. The same q drives the viser preview and the robot each tick, so the picture and the arm move in lockstep. After a successful executed play, the UI auto-cleans up: waypoints clear, the gizmo snaps to the new pose, and Execute un-ticks.

Safety while playing

  • Execute auto-unticks the instant an executed play begins — you re-arm it deliberately each time.
  • Stop breaks the loop and decelerates smoothly (UR servoStop; GoFa holds then lets the EGM session converge out).

Gripper (UR15 only)

A Robotiq Hand-E rides the UR wrist. The "Gripper close %" slider drives it live (0% open → 100% closed) and snaps the on-screen fingers. Capture/Add records the current opening into the waypoint automatically; on replay the gripper actuates only when a waypoint's value changes, after the arm settles. The GoFa has no gripper.

Live follow & free-drive teach

Live (drive robot)

Tick "Live (drive robot)" and the real arm chases the gizmo in real time — no Plan/Play. The gizmo snaps to the current tool first so the arm never lurches toward a stale pose. The tool tracks a straight line to the gizmo (not a joint-space arc). Mutually exclusive with Plan/Play; Stop or un-ticking ends it.

Runs at 125 Hz through an acceleration-limited follower — speed, joint speed and joint accel are all bounded, so a fast drag or an IK branch-flip can't make the arm lurch. The straight-line tool speed is capped by LIVE_MAX_LIN (m/s); raise it for a snappier follow.

Streams over the existing EGM session at 30 Hz. Real tool speed is held under MAX_TCP_SPEED (0.25 m/s, the collaborative limit) by a downstream clamp — so it follows a straight line but stays slow by design. After a long pause the EGM session may drop; the loop detects the stale feed and re-arms on the next motion (expect a brief hitch).

Free-drive (hand-guiding)

Tick "Free-drive" to hand-guide the arm (UR zero-g teachMode; GoFa software lead-through over RWS). Capture records hand-moved poses. Mutually exclusive with Plan/Play/Live; Stop or un-tick releases it.

Save & load trajectories

Waypoint lists save to trajectories/<name>.json (tracked in the repo, so they sync across machines). Load repopulates the waypoints and frames; then Plan to replay.

Headless tools

Replay — play_trajectory.py

./robot_control/bin/python scripts/play_trajectory.py <name> [more names...] \
    [--speed S] [--dry-run] [--no-confirm]

Auto-detects the robot from the file's "robot" field and plays after a [y/N] confirm. Every waypoint must already carry "q" (it's IK-solver-free) — capture taught joints, or Plan-and-save in viser first.

  • --dry-run — print the plan (segments + estimated duration) and exit.
  • --no-confirm — skip the confirmation prompt.
  • Chaining — pass several names to play them back-to-back as one continuous motion (one confirm, gripper state carries across seams). All must target the same robot.
# preview a 3-trajectory chain without moving anything
./robot_control/bin/python scripts/sim.py play pick approach place --dry-run

Record — teleop.py

The record-side counterpart: hand-guide the arm and capture with keypresses to the same JSON format. A live terminal dashboard shows pose, joints, gripper % and waypoint count.

./robot_control/bin/python scripts/teleop.py [name] [--robot ur|gofa]
KeyAction
cCapture a waypoint (live joints + FK pose + gripper)
o / pUR only — open / close the gripper one step
EnterEnd free-drive, save, prompt for the next trajectory
wSoft stop — end free-drive cleanly and exit
qHard stop — protective stop (UR) / halt RAPID (GoFa), then exit

Remote API

Serve HTTP + WebSocket control over the same controller. The network carries high-level goals and telemetry — never the servo loop.

# real hardware, or sim.py for offline
ROBOT_API_TOKEN='a-long-random-secret' \
  ./robot_control/bin/python scripts/real.py api ur15 --host 127.0.0.1 --port 8000

Authentication

Every endpoint needs the token from ROBOT_API_TOKEN (defaults to changeme with a startup warning — set it for anything past a direct cable).

  • HTTP: Authorization: Bearer <token> header.
  • WebSocket: ?token=<token> query parameter.

A bad/missing token → 401 with a WWW-Authenticate: Bearer challenge.

The single-writer lease

Reads and the safety path are open to any authenticated client. All writes require a lease — only one client holds it at a time, so two operators can't fight over the arm.

  1. POST /control/acquire → {"lease_token": "…"} (409 if already held).
  2. Send it as the X-Lease header on every write.
  3. POST /control/release when done.

Acquire with {"force": true} steals a held lease (stopping the current motion first). A write without a valid lease → 423.

Async commands

Writes are non-blocking: validate → submit → return 202 {command_id} immediately. One motion at a time (a second submit → 409 Busy). Track it by polling GET /command/{id} or watching the telemetry stream's active_command.

Endpoint reference

interactive  Click any endpoint to expand its body, response and an example.

GET/healthliveness + robot name

Lease: not required. Returns {"ok": true, "robot": "ur15"}.

curl -s localhost:8000/health -H "Authorization: Bearer $TOK"
GET/statefull state snapshot

Lease: not required. Returns the full RobotState (joints, pose, gripper, safety, activity, active command).

curl -s localhost:8000/state -H "Authorization: Bearer $TOK"
{
  "robot": "ur15",
  "q": [0.0, -1.4, 1.4, -1.4, -1.4, 0.2],   // 6 joints (rad)
  "pose": { "pos": [0.40, 0.10, 0.30], "wxyz": [0,1,0,0] },
  "gripper_frac": 0.0,        // 0 open .. 1 closed; null on GoFa
  "activity": "idle",       // idle | moving | playing | stopped
  "active_command": null,
  "conn_ok": true
}
POST/control/acquiretake the write lease

Lease: n/a. Body (optional) {"force": false}. Returns {"lease_token"}, or 409 if held.

curl -s -X POST localhost:8000/control/acquire \
  -H "Authorization: Bearer $TOK" \
  -H 'Content-Type: application/json' -d '{"force": true}'   # steal
POST/control/releaserelease the lease

Lease: required (X-Lease). → {"released": true}, or 423 with a wrong/absent lease.

curl -s -X POST localhost:8000/control/release \
  -H "Authorization: Bearer $TOK" -H "X-Lease: $LEASE"
POST/move/jointsmove to a joint config (MoveJ)

Lease: required. Body {"q": [6], "speed": 0<…≤1.0}. Interpolates in joint space — exact config, no IK. q is shape/finiteness checked → 422 on a bad vector or speed.

curl -s -X POST localhost:8000/move/joints \
  -H "Authorization: Bearer $TOK" -H "X-Lease: $LEASE" \
  -H 'Content-Type: application/json' \
  -d '{"q": [0.0,-1.4,1.4,-1.4,-1.4,0.2], "speed": 1.0}'
# → 202 {"command_id": 1}
POST/move/posemove to a Cartesian pose (MoveL)

Lease: required. Body {"pos": [x,y,z], "wxyz": [w,x,y,z], "speed"}. IK solves the goal, then the tool tip travels a straight line to it. Pose is the grasp/EE frame (same as /state).

curl -s -X POST localhost:8000/move/pose \
  -H "Authorization: Bearer $TOK" -H "X-Lease: $LEASE" \
  -H 'Content-Type: application/json' \
  -d '{"pos":[0.4,0.1,0.3], "wxyz":[0,1,0,0], "speed":0.5}'
POST/playplay a saved/inline trajectory

Lease: required. Provide one of name (a saved trajectory) or waypoints (inline list), plus optional speed. Segments are straight-line. Missing both → 400; unknown name → 400.

curl -s -X POST localhost:8000/play \
  -H "Authorization: Bearer $TOK" -H "X-Lease: $LEASE" \
  -H 'Content-Type: application/json' \
  -d '{"name": "_sample_ur15", "speed": 1.0}'
POST/gripperset gripper opening (UR only)

Lease: required. Body {"frac": 0.0..1.0} (0 open, 1 closed). On the GoFa (no gripper) → 400.

curl -s -X POST localhost:8000/gripper \
  -H "Authorization: Bearer $TOK" -H "X-Lease: $LEASE" \
  -H 'Content-Type: application/json' -d '{"frac": 0.5}'
GET/command/{id}command status

Lease: not required. Returns the command object; unknown/evicted id → 404 (history keeps the 64 most recent).

curl -s localhost:8000/command/1 -H "Authorization: Bearer $TOK"
# {"id":1,"kind":"moving","status":"done","progress":1.0,"error":null}
# status: running | done | failed | stopped
POST/stop  ·  POST/estopalways-open safety path

Lease: not required — any authenticated client can halt the arm. /stop decelerates gracefully; /estop is a hard stop.

curl -s -X POST localhost:8000/stop  -H "Authorization: Bearer $TOK"
curl -s -X POST localhost:8000/estop -H "Authorization: Bearer $TOK"
WS/telemetrystate stream + heartbeat

Connect ws://host:8000/telemetry?token=…&lease=…. Streams RobotState at ~20 Hz. A matching lease turns the socket into the deadman heartbeat (see below).

Status codes

CodeMeaning
202Write accepted & submitted (command_id returned)
400Bad command content (no name/waypoints, unknown trajectory, gripper on GoFa)
401Missing/invalid bearer token
404/command/{id} unknown or evicted
409Lease already held, or another motion is running (Busy)
422Bad vector (q/pos/wxyz) or speed outside (0, 1.0]
423Write without a valid X-Lease

Telemetry & the deadman watchdog

An open telemetry WebSocket whose ?lease= matches the current lease is a heartbeat. A background watchdog stops the arm and releases the lease if the holder goes silent (no heartbeat, no writes) for watchdog_timeout_s (default 2.0 s) while a motion is running. If your client crashes or the network drops mid-move, the arm stops on its own.

Pattern: hold a /telemetry?…&lease=… socket open for the duration of any motion — at 20 Hz it satisfies the heartbeat automatically.

End-to-end client (Python / httpx)

import time, httpx
BASE, TOK = "http://localhost:8000", "your-token"
auth = {"Authorization": f"Bearer {TOK}"}

with httpx.Client(base_url=BASE, timeout=10.0) as cl:
    lease = cl.post("/control/acquire", headers=auth).json()["lease_token"]
    h = {**auth, "X-Lease": lease}

    cid = cl.post("/move/joints", headers=h,
                  json={"q": [0.0,-1.0,1.0,0.0,1.0,0.2], "speed": 1.0}
                  ).json()["command_id"]

    while cl.get(f"/command/{cid}", headers=auth).json()["status"] == "running":
        time.sleep(0.1)

    cl.post("/control/release", headers=h)

Motion model

CommandPathNotes
/move/jointsMoveJ — joint-space lerpExact configuration reproduced; no IK.
/move/poseMoveL — straight tool linePosition lerp + orientation slerp, IK each tick.
/playMoveL per segmentStraight lines between waypoints; captured configs hit exactly.

Speed. speed is a fraction in (0, 1.0] that scales motion below the configured cap — it can never raise it.

UR15GoFa CRB 15000
GripperHand-E (gripper_frac)none — /gripper → 400
TCP speed capnone on this path0.25 m/s (MAX_TCP_SPEED, collaborative)
Live followaccel-limited, LIVE_MAX_LIN m/sstraight-line, clamped to MAX_TCP_SPEED
"Uses Cartesian" (the path is straight) is separate from speed. The GoFa moves in straight lines but stays capped at 0.25 m/s by its collaborative limit — that's why it's straight but not fast.

Simulation

sim.py runs the real, unmodified scripts against a perfect-tracking kinematic sim by injecting fake transports (rtde_*, hande_gripper, abb_rws, abb_egm) — so every feature works in sim automatically and never drifts from hardware.

./robot_control/bin/python scripts/sim.py ur15                       # UR15 teleop, simulated
./robot_control/bin/python scripts/sim.py gofa                       # GoFa teleop, simulated
./robot_control/bin/python scripts/sim.py api ur15                   # remote API, simulated
./robot_control/bin/python scripts/sim.py play _sample_ur15 --no-confirm
One limitation: there's no physical arm to hand-guide, so free-drive/teach capture just re-grabs the current pose. Author offline with the gizmo, Live, or Plan instead.
